## 1. 核心

旧版は「マイナスをゼロに戻す話」だった。足りない、寒い、壊れた、を毎話埋め戻していた。

リライト版は「ゼロをプラスにする話」にする。暮らしはもともと成り立っている。三ツ辻の仲間は、それを工夫と技でもっと良くしていく。

各話の判定基準は一つ。**読み終えたとき、三ツ辻か仲間の何かが前より良くなっているか。**

### 3つの目標
1. 読者のストレスを軽くする
2. 同じ型の展開・会話をなくす
3. 分かりやすくする

## 2. 世界の再解釈（豊かさA案）

### 2-1. 集落の暮らし
2000年かけて立て直した社会は、すでにそこそこ豊か。江戸後期の宿場町くらいの暮らしに、古代の生物技術が加わっている。

- **灯り**：ヒカリゴケの家灯。夜も手元が見える。贈り物にもなる
- **水**：濾過草（ポンプ・ウィード）を水場に植えれば飲み水になる。どの集落にもある
- **塩**：塩葉樹で日々の味付け程度は賄える。まとまった塩は隊商が運ぶ
- **衛生**：ノシ草（紙の代わり）、蒸し風呂は集落の当たり前の設備
- **食**：ミナシロの米と麦、カネヅカの燻製肉と銅鍋、ハラダの香草と狩猟肉。味噌・醤油・漬物もある

貧しさや欠乏を話の動力にしない。不足が起きても「隊商に頼めば届く」「工夫すれば今日中に何とかなる」範囲に収める。

### 2-2. 三ツ辻の立ち位置
三集落が共同で出資した事業として始まる。最初から次のものがある。
- 隊商の荷車で運んだ資材・食料・道具（数か月分）
- ミナシロの大工が刻んでおいた組み立て式の小屋材（数日で寝床ができる）
- 定期的な隊商便（物資と手紙が届く）

三ツ辻の課題は「生き延びること」ではなく「出資に見合う価値を示すこと」と「自分たちの居場所にすること」。

### 2-3. 景色としての超技術
標塔、動かない星、石柱は、住民にとって生まれたときからある景色。

- 誰も不思議がらない。「昔からある」「天気の目印」くらいの付き合い
- 存在理由は誰も知らない。語り部の伝承にも断片しかない
- 第1話から景色として描いてよい。読者には「明らかに人工物だ」と分かるように書く
- 何のためにあるのか（＝宇宙船であること）は段階的に明かす（→6節）

**標塔は壊れない（厳守）**：標塔は外殻・地下殻と一続きのMTMアロイ構造体で、衝撃も熱も全体に瞬時に分散される。傾く・折れる・欠ける・傷が付く・汚れが落ちない、といった描写はしない。一部だけが壊れることはなく、壊れるなら世界全体が一斉に崩壊する。危機は形の崩れではなく、機能の停止（石柱の制御が効かない、霧・季節の乱れ、ノード間の通信が途絶える）として描く（→99_矛盾リスト M052）。

**標塔は六角形の頂点に並ぶ**：地図に六角形を敷き詰めたときの頂点に標塔が立つ（作者の図：辺境拠点日誌/設定/三ツ辻拠点.png）。隣の標塔までは約37.5km。三ツ辻は中央の六角形の中にあり、カネヅカ・ハラダ・ミナシロはそれぞれ隣の六角形の中にある。標塔の位置は手で置かず、位置データ.json の格子から計算する（→M054）。

### 2-3-2. 迷わずに旅ができる理由
地図も整備された道もないが、旅慣れた者は迷わない（→04「星と標塔による道案内」、99 U028）。
- **頭上の星**：地表約7.85kmで頭上の星が1度ずれる。集落ごとの「頭上の星」を星歌で覚える
- **柱重ね**：2本の標塔が重なる線をつないで進む
- **神代の道の筋**：A番号の石柱の上は地面が固く、一本の筋として残る
- **石柱の番号**：読めればセル内の位置が分かる。読めるのはカイだけ（カイの見せ場）
- **弱点**：曇り・霧では動かずに待つ。破れば遭難する（事件回の材料）

物語での使い道：三ツ辻の野廻り隊が、星と柱重ねで測った正確な地図を作る。地図は隊商に売れ、三ツ辻の価値になる（「ゼロをプラスにする」の軸の一つ）。

### 2-3-3. 太陽と空
- 太陽は天井のパネルが映す像で、各地点に平行な光として届く。影は普通に揃う。昼夜は全域同時刻（→02「5」、U027）
- 太陽の動力源（ソル・ユニット）は赤道の真上を回るため、居住帯からは見えない（U026）
- 星は2000年前のまま動かない。暗転したパネルは「失われた星座」として、決まった地域の上空に暗い穴として見える

### 2-4. 危険な生き物
対処法が伝わっている相手として扱う。正しい知識と技があれば勝てる。野廻り隊の見せ場の材料にする。

### 2-5. トラブルの扱い
- 嵐・故障・獣害は起きてよい。ただし同じ話か次の話で片付ける
- 片付けた結果は「元に戻る」ではなく「前より良くなる」
- 「二週間かかる」「冬じゅう我慢する」のような長い我慢を描かない

## 3. 人物の見せ場

超人ではなく「その道のプロ」として活躍させる。一人に一つ、読者が覚えられる決め技を持たせる。能力は隠さず、早めに見せる。

| 人物 | 決め技 | 見せ方の例 |
|---|---|---|
| カイ | 古代文字の読解、人並み外れた体（ナノマシン） | 誰も読めない刻みを読む。疲れない、重い物を一人で運ぶ。本人は理由を知らない |
| ガン | 大型の獣を仕留める罠、地形の読み | 地面を一目見て罠の位置を決め、獣が狙いどおりにかかる |
| ミコト | 決定的な一射、遠目 | 群れの先頭の足元に一射して向きを変える。誰も見つけていない影を先に見つける |
| リュウ | 薬と調合、痕跡からの推理 | 糞と足跡から獣の数と行き先を言い当てる。煙や匂いの調合で獣を動かす |
| スズ | 一度通った道を忘れない、身軽さ | 道案内、偵察、高所。嵐の中でも迷わない |
| ハナ | 料理 | 三集落の食材を合わせた料理。客人の評価を料理で変える |
| クワ | 建築と修繕 | 嵐で他が壊れても三ツ辻だけ持ちこたえる設計 |

### 3-0. 作者の方針（2026-11-04）
- **野廻り隊は五人で動く**：旧版は二〜三人での行動が多かった。リライト版は五人で動くのを基本にする。分かれるのは、分かれることに話の上の意味があるときだけ（別々の場所で同時に何かが起きる、二手に分かれる作戦など）
- **可愛いところを出す**：旧版は硬派な人物ばかりで、可愛い担当がミルクだけだった。スズとミコトの可愛いところを見せ、拠点に常駐する野廻り隊以外の若者（アサ）を早めに出す（→登場人物_リライト.md「可愛いところ」）
- **早めに仲良くさせ、楽しい会話をさせる**：旧版は必要なこと以外の会話がほとんどなかった。第1章のうちに五人を仲良くさせ、用事のない雑談、軽口、くだらない言い合いを毎話入れる。移動の途中、食事、作業の合間が雑談の場所

### 3-1. 承認の描写
章ごとに最低1回、外の人（三集落、隊商、旅人）が三ツ辻の仕事に驚く・頼る・噂する場面を入れる。

### 3-2. カイの天然
カイの的外れに聞こえる一言が実は正解、という型は持ち味なので残す。ただし1章に1〜2回まで。

### 3-3. 口癖の扱い
旧版の人物設定にある口癖・定番いじりは、そのまま使い回さない。
- 口癖は人物ごとに一つだけ残し、1話に1回までにする
- 「定番いじり」の固定パターン（「また試しましたね」「三行で」「ほっとけ」「ロマンがないですね」など）は廃止する。掛け合いは毎回その場の出来事から作る
- 「……ペットです」のような天丼は、使うなら章に1回まで

## 4. 話の型と重複防止

### 4-1. 話の型
各話に主になる型を一つ割り当てる。割り当ては「話割り当て表」で管理する。

| 記号 | 型 | 中身 |
|---|---|---|
| 探 | 探索 | 未知の場所へ行く。地図が広がる |
| 狩 | 狩り・戦い | 獣と対決する。技の見せ場 |
| 作 | ものづくり | 施設や道具を作る。拠点が育つ |
| 交 | 交易・交渉 | 隊商や集落と取引する。駆け引き |
| 食 | 食事・祭り | 料理、宴、行事。くつろぎ回 |
| 謎 | 謎解き | 石柱・標塔・父の記録を読み解く |
| 客 | 来訪者 | 外から誰かが来て、三ツ辻が外の目で見られる |
| 人 | 人物回 | 一人を掘り下げる。過去や悩み |
| 事 | 事件 | 嵐・遭難・救出など突発の出来事 |

### 4-2. 割り当てのルール
- 同じ型を2話続けない
- 1章（約8話）に5種類以上の型を入れる
- 会議・話し合いの場面は1章に1回まで。決めごとは現場で動きながら決める
- 「全員が集まって一人一行ずつ案を出す」場面は書かない

### 4-3. 1話の組み立て
- **冒頭3行**：今日は何をする話かを示す
- **中盤**：誰かの技が決まる見せ場を必ず一つ置く
- **締め**：成果（何が良くなったか）か、次への引きで終える
- **工程の告知で引かない**：「次は水です」のような、次にやる作業の告知だけで終えない（試し書きの読者評価で「工程表を読んでいる感じ」と指摘された）
- **毎話、謎を一つ小さく動かす**：神代の道、石柱、標塔、ミルク、父のメモのどれかを、一話に一つ、ほんの少し進める
- **障害を一つ置く**：一日で何の抵抗もなく片づく話を続けない。反対する人、予想外の獣の動き、地面の固さなど、小さな障害を一つ置いてから解く

### 4-5. 試し書きで見つかった繰り返しの型（2026-11-03）
- 同じ解決の型を続けない：「三つの集落のやり方を重ねて解決」は第1話の鍋で使った。続けて使わない
- 同じ組み合わせの場面を続けない：見張りの二人、夜の静かな会話など
- 人物を順番に並べる列挙（4人の偵察、6件の注文など）は一話に一回まで。完成の場面で同じ列挙を繰り返さない
- 不器用な肯定の描写（「耳が赤い」「それが、この人なりの返事らしい」など）と、地の文の一言ツッコミ（「響くだけである」「できるらしい」など）は、一話に数か所まで
- 仕草の重複（額に手を当てる、など）を話をまたいで続けない
- **主人公が毎話一つ決める**：カイの知識（語り部の話、古代文字）か体（丈夫さ）がなければ解けない場面を、毎話一つ置く。発見の役をいつも仲間に回さない。カイが見当をつけ、仲間が確かめる形も使える（第3話の浅瀬）
- **大人がすぐ折れる解決を続けない**：「年長者が反発→若手の一言→すぐ認める」は第1〜3話で何度も使った。年長者の言い分が正しかった、譲る代わりに代償を払う、結論を次の話へ持ち越す、などに変える
- **「XではないY」の言い回し**（「囲うのではない。案内する」など）は一話に一回まで
- **人物紹介を「出身・職・名前・外見」の同じ順で続けない**：行動の場面に散らす

### 4-4. 禁止・制限する表現
旧版で多用されていたもの。

| 表現・場面 | 旧版の回数 | リライト版の扱い |
|---|---|---|
| 「黙った」 | 78回 | 1話1回まで |
| 「間を置いた」 | 44回 | 1話1回まで |
| 「帳簿」 | 194回 | ドウの描写の決まり文句にしない |
| ミルク・バターが草を食む締め | 多数 | 締めには使わない。見せ場は数話に一度 |
| 星・空を見上げる余韻の締め | 多数 | 章末に限る |
| 「静かにうなずいた」締め | 多数 | 使わない |
| 椀を配る食事描写 | 「椀」75回 | 料理の中身と味を書く |
| 「足りない」 | 56回 | 話の動力にしない |

## 5. 分かりやすさ

- **登場人物を絞る**：1話で新しく名前を出すのは3人まで。例外は第1話で、野廻り隊の5人と、もう1人（ハナ）までとする。ドウは第1話では「管理役」と呼び、名前は第2話で出す。30人の大半は「ミナシロの大工たち」のようにまとめて呼ぶ
- **記号を通称にする**：A/B/C/F番号、B-7などの記号は本文で使わない。「北の塔」「崖下の柱」のような通称にする。記号が必要なら地図の注記にとどめる
- **用語は一度だけ短く説明する**：初出時に会話か一文で説明し、以後は説明しない
- **時間経過を明記する**：章の冒頭か話の冒頭で「拠点ができて二か月」のように示す
- **方角・距離・所要時間は台帳から引く**：→ 5-1節

### 5-1. 位置の運用ルール
旧版では、同じ場所の方角や距離が登場のたびに揺れた。原因は、正とされる資料が複数あったこと、縮尺のない地図、数字どうしの矛盾、単位の混在だった。リライト版は次のように運用する。

- **正は `位置データ.json` の一つだけ**。三ツ辻を原点に、方位角と直線距離で全地点を置く
- `python scripts/rewrite_places.py` で **位置台帳.md と 位置地図.svg（縮尺どおり）を自動生成**する。台帳と地図は手で直さない
- 所要時間は共通の速さのモデルから計算する。本文で日数や時間を変えるときは、迂回・天候などの理由を本文に書く
- **新しい場所は、本文に書く前に位置データ.json に登録する**。一度しか出ない場所（倒木、野営地など）も登録する
- 地点どうしの方角・距離（「禁域の入口から南南西の標塔まで」など）も台帳の「地点どうしの位置関係」から引く。必要な組は位置データ.json の「地点間」に足す
- 単位は「時間・分・キロ」に統一する。「刻」は使わない
- 標塔の名前（「北の標塔」など）は三ツ辻から見た方角で付いている。名前と実際の方角が食い違うと、生成スクリプトがエラーを出す
- 割り当て表には、各章で使う地点を書いておく
- 各話を書いたら `python scripts/check_rewrite_places.py <話のファイル>` で照合する。

### 5-2. 標塔の呼び名のルール
方角で付けた名前は、見る場所によって指す標塔が変わる。たとえば北の標塔（図のA）は、カネヅカから見ると東にあり、カネヅカに一番近い標塔でもある。読者が混乱しないよう、次のように書く。

- **地の文の呼び名は一つに固定する**：台帳の「名前」だけを使う。名前は三ツ辻から見た方角で付けてあり、旅先でも、他の集落の場面でも変えない
- **三ツ辻を囲む6本以外の標塔には、方角を含まない固有名を付ける**（例：V＝点検口の標塔）。無名の標塔を本文に出すときは、先に位置データ.json で名前を付ける
- **方角は名前と分けて書く**：「北の標塔は、ここからだと東に見えた」。「東に見える標塔」「東の空の標塔」のように、方角と「標塔」を続けた言い方はしない（名前と紛れる）
- **他の集落の人の呼び方**：台詞でその集落での言い方（カネヅカの「東の柱」など）を使う場合は、直後の地の文で三ツ辻での名前を示す。できれば台詞でも「カネヅカのそばの標塔」のように方角を含まない言い方にする
- **書く前に台帳の「見る場所によって変わる標塔の方角」を見る**：その場面の場所から見て、呼び名がぶつかる組を確認する
- チェッカーは「〈集落〉から見た／〈集落〉の〈方角〉の標塔」「〈方角〉に見える標塔」の形を「要確認」として拾う「要確認」は目で確かめる（地点を基準にした方角などで誤検知が出る）

## 8. 設定との整合

次の確定事項は守る（CLAUDE.md・99_矛盾・未解決事項リスト.md）。
- 人工太陽は投影方式。昼夜は全域同時刻。発光体が頭上を通る描写はしない
- 隣接集落は10〜20km、中核集落間は60〜70km
- 危機の顕在化は約10年前から
- 生き物の変異の原因は拡散MTMにしない
